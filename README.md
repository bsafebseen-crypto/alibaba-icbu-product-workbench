# 国际站自动上品工作台

这是一个运行在本机的商品内容工作台。当前支持从本地图片和 XLSX/CSV/TXT 词表建立 1 个基础品与 4 个类似品，也可以读取一个线上主产品的 Schema，结合 4 张类似品主图、副图素材池和关键词表生成 4 套类似品内容。工作台还包含一个与国际站完全隔离的“1688 自动发品”入口，用于官方开放平台的授权诊断、类目规则、本地预检和单商品安全闭环。

## 启动

双击项目根目录中的 `启动工作台.cmd`。浏览器会打开：

`http://127.0.0.1:54025/`

双击脚本或桌面快捷方式后，服务在独立后台运行；启动窗口会自动关闭，关闭浏览器也不会停止服务。再次打开快捷方式会复用已经运行的服务，不会重复启动。服务仅监听本机地址 `127.0.0.1`，不会向局域网开放。

需要退出后台时，双击 `停止工作台.cmd` 并确认。脚本只请求正常关闭当前服务；商品正在写入、处于安全间隔或图片正在处理时会拒绝停止，不强制结束进程。此功能不包含开机自启、异常自动重启或自动发布。运行诊断保存在 `data/runtime/server.log`。

首次启动时，脚本会按照 `package-lock.json` 自动运行 `npm ci` 安装依赖；后续启动不会重复安装。

## 图片工具

从左侧导航进入 **图片工具**，点击「选择文件夹」选择本机原图片文件夹，再点击「开始处理」。处理结果、进度和跳过的文件统一显示在当前页面的结果区域，无需另外打开桌面程序。

本模块直接复用已有 Python 图片处理核心：只处理所选文件夹第一层图片，按文件名中的数字顺序排列，统一缩放到 **800×800**，并在原文件夹内替换为 `1.jpg、2.jpg、3.jpg……`。不创建永久结果子文件夹。正方形图片保持比例，长方形直接拉伸；透明区域铺白，照片按 EXIF 方向纠正，多帧图只取第一帧。

支持 JPG/JPEG、PNG、WebP、BMP、TIF/TIFF、GIF。损坏图片跳过并保留；占用输出编号的不可替换项目会阻止处理。全部缩放完成后再统一替换，失败时尝试恢复原文件，恢复未完成时显示临时原图的位置。页面切换或关闭浏览器不会取消正在运行的处理；重新进入页面可查看当前状态，同一次选择不会自动重复执行。

图片工具需要 **Python 3.10+（含 tkinter）和 Pillow**，现有其他模块不需要 Python。安装 Python 后，在项目根目录执行一次：

```powershell
python -m pip install -r tools/image-batch/requirements.txt
```

继续使用原来的 `启动工作台.cmd` 或 `npm start` 启动。环境缺失时只在图片工具页面提示，不影响其他功能；本模块不调用阿里写接口或 AI，不迁移现有任务数据。

## 工作台模块

工作台包含以下模块：

- 运营概览：统计本机已保存批次、商品总数、完整预览和待处理商品
- 产品池：搜索、筛选、排序和分页查看本地商品，并可导出当前筛选结果为 UTF-8 CSV
- 自动上品：读取主产品或从本地新建 1+4，编辑图片、文案、FAQ 与自定义属性
- 关键词记录：按 Product ID 在本机保存询盘词与可选 Product ID 的直通车屏蔽词；数据写入 `data/keyword-records.json`，不调用阿里或 AI 接口
- 关键词表：导入 XLSX、CSV、TXT 词表
- AI 接口：配置兼容模型 API
- 1688 自动发品：使用独立凭证读取国内站类目和动态 Schema，生成单商品预览并保存安全任务
- 阿里接口：配置 OAuth、只读 Schema 和图片银行上传

产品池详情抽屉只读取 `data/tasks/` 中经过清理的任务数据，可查看图片银行链接、文案、属性、FAQ 和 Schema 变更字段。它不会显示原始 Schema XML、API Key、App Secret、Access Token 或图片 Base64。

## 哪些操作消耗模型 Token

不会消耗模型 Token：

- 选择和整理本地图片
- 读取 XLSX/CSV/TXT 词表
- 读取线上主产品 Schema
- 创建 5 个手工版本
- 编辑标题、卖点和关键词
- 分配主图与副图
- 保存任务 JSON

会调用模型并产生模型服务商用量：

- 测试 AI 连接
- AI 生成 5 份商品文案
- AI 结合图片生成 4 套类似品标题、卖点、FAQ 和自定义属性差异

## AI 设置

页面预置了 OpenAI、DeepSeek、阿里云百炼、硅基流动和自定义兼容接口的 Base URL。模型名称需要填写服务商控制台显示的 Model ID。

API Key 不写入任务 JSON、日志或 Obsidian。默认只放在浏览器会话存储中；勾选“在这台电脑的浏览器中记住”后，才会写入本机浏览器存储。

预置地址参考服务商官方文档：

- OpenAI：<https://platform.openai.com/docs/api-reference>
- DeepSeek：<https://api-docs.deepseek.com/zh-cn/>
- 阿里云百炼：<https://help.aliyun.com/zh/model-studio/base-url>
- 硅基流动：<https://docs.siliconflow.cn/cn/userguide/quickstart>

## 使用流程

1. 在左侧选择服务商，填写 API Key 和模型名称；如果只使用手工模式，可以不填。
2. 上传 4 张类似品主图，并上传至少 5 张副图素材；4 张主图按顺序对应类似品 1–4。
3. 选择 XLSX、CSV 或 TXT 词表，并补充确定无误的商品事实。
4. 从线上主产品生成类似品时，点击“AI 生成 4 套类似品”。支持识图的模型会同时分析压缩后的图片；模型拒绝图片时，工作台会询问是否改用纯文字模式，不会静默回退。
5. 在商品标签中逐个检查标题、主题卖点、FAQ 前 5 条、自定义属性差异和图片组合。
6. 点击“确认上传分配图片”，在二次确认后把当前四套实际使用的图片上传到图片银行。
7. 图片全部上传后点击“生成含图片的完整预览”，逐套检查本地 Schema 变更摘要。
8. 点击“保存任务”。

任务文件保存在：

`data/tasks/`

## 阿里店铺授权

“阿里接口”页面已支持 OAuth 授权码换取 Access Token，并会同时保留用于后续续期的 Refresh Token。

1. 填写 App Key 和新生成的 App Secret。
2. 点击“打开阿里授权页”并完成店铺授权。
3. 页面跳转到 Alibaba.com 后，复制地址栏中的完整网址。
4. 粘贴到工作台的“授权后网址或 Code”，点击“换取 Access Token”。
5. 点击“测试阿里连接”，工作台只调用只读商品 Schema 接口进行验证。

当前应用登记的回调地址是 `https://www.alibaba.com`，因此第一版需要复制一次授权后的网址；以后把开放平台回调改为本地可接收地址后，可以取消这一步。

### 沿用线上主产品

在“自动上品”中填写主产品的数字 ID，工作台会调用只读接口 `alibaba.icbu.product.schema.render` 读取现有商品的完整 Schema，并创建 4 个类似品编辑位。这个步骤不会修改原商品，也不会创建草稿。

读取成功后，工作台会显示标题、主题卖点、FAQ、自定义属性和商品图片五项识别状态，并把原商品内容填入四个类似品。每套自定义属性完整继承主产品，AI 最多提出 5 项新增、修改或删除；未变化属性保持原值。FAQ 只替换前 5 条，第 6 条及以后保持原值。

生成内容后点击“生成 4 份本地预览”，工作台会分别生成四份预览 XML 和变更摘要；完整 XML 只保存在本地任务中，不会发送给大模型，也不会提交到阿里。

如果某个字段显示“需确认”，工作台会禁用预览生成，避免猜错字段后覆盖价格、SKU、图片、标准属性或详情。真实类目的字段名称可能存在差异，需要用一次只读加载结果补充字段别名。

图片默认只在浏览器内用于识图、预览和分配。准备好 4 张主图和每套 5 张副图后，可以点击“确认上传分配图片”，由工作台逐张调用 `alibaba.icbu.photobank.upload`。上传前会再次弹窗确认；已成功的图片会记录返回的 `file_id` 和 `photobank_url`，中断重试时不会重复上传。任务 JSON 只保存图片文件名、分配索引和图片银行返回信息，不保存图片 Base64。

图片上传完成后，“生成含图片的完整预览”才会启用。工作台按照每套商品当前的分配顺序，把一张主图和五张副图的 `fileId + photobankUrl` 写入 `scImages_0..5`。这一步只在本地生成四份完整 XML，不调用草稿、修改或发布接口；重新选择图片或调整分配后，需要重新生成完整预览。

Obsidian 模块的逐份草稿使用 `alibaba.icbu.product.schema.add.draft`；旧“自动上品”模块保持本地预览模式。每张 Obsidian 方案卡另有红色“直接正式发布此产品”按钮，单击后仅对当前一件调用一次 `alibaba.icbu.product.schema.add`，不先创建草稿，也不弹第二次确认框。

## 1688 自动发品

该模块只使用 1688 国内站开放平台的独立网关、App Key、App Secret、Access Token 和 Refresh Token，不读取也不覆盖国际站 ICBU 凭证。Secret 和 Token 默认只放在浏览器会话存储中；即使选择本机记住，也不会写入 Git、日志或 `data/tasks/1688-*.json`。

安全流程为：只读连接诊断 → 搜索叶子类目 → 读取 `alibaba.new.product.getSchema` 动态规则 → 人工确认图片上传 → 本地填写商品 → 只读预检和请求摘要 → 保存任务 → 单件确认发布 → 官方商品查询核验。任务在页面刷新或服务重启后可恢复；一旦进入发布中、待核验或不确定状态，原写机会即被消耗，只能只读核验，不能自动重发。

`npm start` 默认硬关闭 1688 真实商品发布。只有在功能、自动测试、账号只读权限和请求摘要全部核对完成，并由操作者明确同意首次单商品测试后，才可在同一个 PowerShell 窗口临时设置：

```powershell
$env:WORKBENCH_1688_ALLOW_WRITES = '1'
npm start
```

停止该进程后该临时开关失效。不要把它写入启动脚本或 `.env`。即使开关开启，页面仍要求写权限诊断、官方前端 SDK、最新 Schema、预检、持久化任务和当前单件确认全部通过。开发和自动化测试只使用 mock/fake，不访问真实写接口。官方接口及权限研究见 [`docs/1688-api-research.md`](docs/1688-api-research.md)。

## 当前边界

当前允许三类受控写操作：经二次确认的图片银行上传、Obsidian 模块中经逐商品确认的草稿创建，以及方案卡上一键触发的单商品正式发布。两个商品按钮都只在完整预览通过后启用并绑定当前预览指纹；每次只提交当前一份，不会连带处理其他方案。

草稿提交前工作台先把 `submitting` 状态写入本地安全任务文件。正式发布前会读取同标题商品 ID 基线，持有覆盖草稿和正式发布的全局写锁，并先持久化 `publishing` 状态；一次尝试最多写入一次，完成后固定等待 3 秒再开放下一件。

正式发布返回 ID 后，工作台会通过正式商品读取接口精确核对标题、卖点、5 条 FAQ、10 条自定义属性和 6 张图片 ID 顺序，全部一致才显示成功。网络超时、响应损坏或返回 ID 暂不可读时不会重新发布，而是按 2、5、10、20、30、60 秒及之后每 5 分钟的节奏只读找回，最长 24 小时。页面刷新或服务重启后，在浏览器提供阿里凭证时继续只读核验；零候选继续等待，多个候选保持歧义状态，均禁止重复写入。

当前没有商品更新、上下架、删除或库存修改调用。正式发布和自动核验是确定性脚本流程，不调用大模型、不消耗模型 Token。

已创建草稿会保留安全的本地任务记录。工作台重启后可点击“读取并核对草稿”，只读调用 `alibaba.icbu.product.schema.render.draft`，逐项核对标题、卖点、前 5 条 FAQ、10 条自定义属性，并检查 6 张图片的图片银行标识和地址是否完整。核对结果不包含原始 XML、密钥或 Token，也不会修改、重建或发布商品。

### Obsidian 五方案导入

“Obsidian 上品”模块只扫描固定目录 `C:\obsidian\obsidian\国际站发品` 下的 Markdown 文件，不监听目录，也不会自动启动任务。每个可导入文件必须恰好包含一个版本化机器数据块：

````markdown
<!-- alibaba-listing-batch:start -->
```json
{"schemaVersion":1,"batchId":"reflective-vest-001","batchName":"Reflective Vest","plans":[]}
```
<!-- alibaba-listing-batch:end -->
````

`plans` 必须正好有 5 套；每套需要唯一 `id`、非空 `title`、`sellingPoints`、5 组完整 `faqs` 和 10 组名称不重复的 `customAttributes`。旧版本、缺项、重复方案或目录外路径会被阻止。

载入后选择已经手动发布的母商品方案，并在页面里填写对应商品 ID；工作台会保留其余四套方案的原始顺序。点击“只读加载母商品 Schema”后，工作台依次调用商品 ID 加密、单商品详情和 `schema.render`，从真实商品详情取得类目与商品类型，再按开放平台当前英文发布契约生成源 Schema；不会修改母商品。

每个剩余方案单独选择 6 张本地图片，选择顺序固定为 1 张主图加 5 张副图。工作台会在弹窗确认后把实际使用的图片上传到图片银行，再生成四份完整本地预览。严格预览只允许改变标题、主题卖点、FAQ 前 5 条、全部 10 条自定义属性和 6 张商品图；其他 Schema 子树经过结构比较，任何额外变化都会阻止预览。

导入、只读商品检查、本地预览、草稿创建、正式发布和自动核验都不产生模型 Token 用量。图片银行上传保留二次确认；预览通过后，每张方案卡可选择单独确认调用一次 `schema.add.draft`，或单击红色按钮直接正式发布当前一件。源 Schema 和预览 XML 只存在于活动服务内存/响应中，本地任务只保存指纹、安全状态、基线与候选商品 ID、草稿或正式商品 ID 和追踪信息。
