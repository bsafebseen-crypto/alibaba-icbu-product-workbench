# 国际站自动上品工作台

这是一个运行在本机的商品内容工作台。当前支持从本地图片和 XLSX/CSV/TXT 词表建立 1 个基础品与 4 个类似品，也可以读取一个线上主产品的 Schema，结合 4 张类似品主图、副图素材池和关键词表生成 4 套类似品内容。

## 启动

双击项目根目录中的 `启动工作台.cmd`。浏览器会打开：

`http://127.0.0.1:54025/`

关闭启动脚本的黑色窗口即可停止工作台。服务仅监听本机地址 `127.0.0.1`，不会向局域网开放。

首次启动时，脚本会按照 `package-lock.json` 自动运行 `npm ci` 安装依赖；后续启动不会重复安装。

## 换一台 Windows 电脑继续开发

完整换机与接手步骤见 [`WORK_MACHINE_SETUP.md`](WORK_MACHINE_SETUP.md)。

工作机只需要预先安装：

- Git
- Node.js 20 或更高版本（安装包自带 npm）

克隆仓库后可以直接双击 `启动工作台.cmd`。也可以在 PowerShell 中运行：

```powershell
npm ci
npm test
npm start
```

GitHub 仓库只包含源代码、锁定依赖版本的 `package-lock.json`、测试和文档。`node_modules/` 不需要上传，会在工作机重新安装；API Key、App Secret、Token、`data/tasks/`、本地图片、`.env`、日志和临时文件均不会进入仓库。

如果工作机使用不同端口，可在启动前设置 `ICBU_WORKBENCH_PORT`。默认端口为 `54025`，服务始终只监听本机地址。

## 工作台模块

左侧导航目前包含六个模块：

- 运营概览：统计本机已保存批次、商品总数、完整预览和待处理商品
- 产品池：搜索、筛选、排序和分页查看本地商品，并可导出当前筛选结果为 UTF-8 CSV
- 自动上品：读取主产品或从本地新建 1+4，编辑图片、文案、FAQ 与自定义属性
- 关键词表：导入 XLSX、CSV、TXT 词表
- AI 接口：配置兼容模型 API
- 阿里接口：配置 OAuth、只读 Schema 和图片银行上传

产品池详情抽屉只读取 `data/tasks/` 中经过清理的任务数据，可查看图片银行链接、文案、属性、FAQ 和 Schema 变更字段。它不会显示原始 Schema XML、API Key、App Secret、Access Token 或图片 Base64。

## 哪些操作消耗模型 Token

不会消耗模型 Token：

- 选择和整理本地图片
- 读取 XLSX/CSV/TXT 词表
- 读取线上主产品 Schema
- 创建 5 个手工版本
- 编辑标题、卖点和关键词
- 分配主图与副图
- 保存任务 JSON

会调用模型并产生模型服务商用量：

- 测试 AI 连接
- AI 生成 5 份商品文案
- AI 结合图片生成 4 套类似品标题、卖点、FAQ 和自定义属性差异

## AI 设置

页面预置了 OpenAI、DeepSeek、阿里云百炼、硅基流动和自定义兼容接口的 Base URL。模型名称需要填写服务商控制台显示的 Model ID。

API Key 不写入任务 JSON、日志或 Obsidian。默认只放在浏览器会话存储中；勾选“在这台电脑的浏览器中记住”后，才会写入本机浏览器存储。

预置地址参考服务商官方文档：

- OpenAI：<https://platform.openai.com/docs/api-reference>
- DeepSeek：<https://api-docs.deepseek.com/zh-cn/>
- 阿里云百炼：<https://help.aliyun.com/zh/model-studio/base-url>
- 硅基流动：<https://docs.siliconflow.cn/cn/userguide/quickstart>

## 使用流程

1. 在左侧选择服务商，填写 API Key 和模型名称；如果只使用手工模式，可以不填。
2. 上传 4 张类似品主图，并上传至少 5 张副图素材；4 张主图按顺序对应类似品 1–4。
3. 选择 XLSX、CSV 或 TXT 词表，并补充确定无误的商品事实。
4. 从线上主产品生成类似品时，点击“AI 生成 4 套类似品”。支持识图的模型会同时分析压缩后的图片；模型拒绝图片时，工作台会询问是否改用纯文字模式，不会静默回退。
5. 在商品标签中逐个检查标题、主题卖点、FAQ 前 5 条、自定义属性差异和图片组合。
6. 点击“确认上传分配图片”，在二次确认后把当前四套实际使用的图片上传到图片银行。
7. 图片全部上传后点击“生成含图片的完整预览”，逐套检查本地 Schema 变更摘要。
8. 点击“保存任务”。

任务文件保存在：

`data/tasks/`

## 阿里店铺授权

“阿里接口”页面已支持 OAuth 授权码换取 Access Token，并会同时保留用于后续续期的 Refresh Token。

1. 填写 App Key 和新生成的 App Secret。
2. 点击“打开阿里授权页”并完成店铺授权。
3. 页面跳转到 Alibaba.com 后，复制地址栏中的完整网址。
4. 粘贴到工作台的“授权后网址或 Code”，点击“换取 Access Token”。
5. 点击“测试阿里连接”，工作台只调用只读商品 Schema 接口进行验证。

当前应用登记的回调地址是 `https://www.alibaba.com`，因此第一版需要复制一次授权后的网址；以后把开放平台回调改为本地可接收地址后，可以取消这一步。

### 沿用线上主产品

在“自动上品”中填写主产品的数字 ID，工作台会调用只读接口 `alibaba.icbu.product.schema.render` 读取现有商品的完整 Schema，并创建 4 个类似品编辑位。这个步骤不会修改原商品，也不会创建草稿。

读取成功后，工作台会显示标题、主题卖点、FAQ、自定义属性和商品图片五项识别状态，并把原商品内容填入四个类似品。每套自定义属性完整继承主产品，AI 最多提出 5 项新增、修改或删除；未变化属性保持原值。FAQ 只替换前 5 条，第 6 条及以后保持原值。

生成内容后点击“生成 4 份本地预览”，工作台会分别生成四份预览 XML 和变更摘要；完整 XML 只保存在本地任务中，不会发送给大模型，也不会提交到阿里。

如果某个字段显示“需确认”，工作台会禁用预览生成，避免猜错字段后覆盖价格、SKU、图片、标准属性或详情。真实类目的字段名称可能存在差异，需要用一次只读加载结果补充字段别名。

图片默认只在浏览器内用于识图、预览和分配。准备好 4 张主图和每套 5 张副图后，可以点击“确认上传分配图片”，由工作台逐张调用 `alibaba.icbu.photobank.upload`。上传前会再次弹窗确认；已成功的图片会记录返回的 `file_id` 和 `photobank_url`，中断重试时不会重复上传。任务 JSON 只保存图片文件名、分配索引和图片银行返回信息，不保存图片 Base64。

图片上传完成后，“生成含图片的完整预览”才会启用。工作台按照每套商品当前的分配顺序，把一张主图和五张副图的 `fileId + photobankUrl` 写入 `scImages_0..5`。这一步只在本地生成四份完整 XML，不调用草稿、修改或发布接口；重新选择图片或调整分配后，需要重新生成完整预览。

Obsidian 模块的逐份草稿使用 `alibaba.icbu.product.schema.add.draft`；旧“自动上品”模块保持本地预览模式。正式发布接口 `alibaba.icbu.product.schema.add` 仍未启用。

## 当前边界

当前允许两类受控写操作：经二次确认的图片银行上传，以及 Obsidian 模块中经逐商品确认的草稿创建。草稿按钮只在四份完整预览通过后出现，并绑定当前预览指纹；每次只提交一份，不会自动继续下一份，也不会自动上线商品。

提交前工作台先把 `submitting` 状态写入本地安全任务文件。阿里明确拒绝时记录失败；网络超时、响应损坏或结果不明确时记录 `result_unknown` 并永久禁用该次重试，必须先到阿里后台按标题与时间核对。当前没有商品更新、上下架或正式发布调用。

### Obsidian 五方案导入

“Obsidian 上品”模块只扫描固定目录 `C:\obsidian\obsidian\国际站发品` 下的 Markdown 文件，不监听目录，也不会自动启动任务。每个可导入文件必须恰好包含一个版本化机器数据块：

````markdown
<!-- alibaba-listing-batch:start -->
```json
{"schemaVersion":1,"batchId":"reflective-vest-001","batchName":"Reflective Vest","plans":[]}
```
<!-- alibaba-listing-batch:end -->
````

`plans` 必须正好有 5 套；每套需要唯一 `id`、非空 `title`、`sellingPoints`、5 组完整 `faqs` 和 10 组名称不重复的 `customAttributes`。旧版本、缺项、重复方案或目录外路径会被阻止。

载入后选择已经手动发布的母商品方案，并在页面里填写对应商品 ID；工作台会保留其余四套方案的原始顺序。点击“只读加载母商品 Schema”后，工作台依次调用商品 ID 加密、单商品详情和 `schema.render`，从真实商品详情取得类目与商品类型，再按开放平台当前英文发布契约生成源 Schema；不会修改母商品。

每个剩余方案单独选择 6 张本地图片，选择顺序固定为 1 张主图加 5 张副图。工作台会在弹窗确认后把实际使用的图片上传到图片银行，再生成四份完整本地预览。严格预览只允许改变标题、主题卖点、FAQ 前 5 条、全部 10 条自定义属性和 6 张商品图；其他 Schema 子树经过结构比较，任何额外变化都会阻止预览。

导入、只读商品检查和本地预览不产生模型 Token 用量。图片银行上传保留二次确认；四份预览通过后，每张方案卡可单独确认调用一次 `schema.add.draft`。源 Schema 和预览 XML 只存在于活动服务内存/响应中，本地任务只保存指纹、状态、草稿 ID 和追踪信息。`schema.add` 正式发布仍被禁止。
