# 1688 图片上品

## 核心原则

先判断图片能证明什么，再扩展采购搜索表达。词库只提供候选叫法，不假装具有搜索量数据；所有材质、尺寸、重量和反光材料预测都显式标注证据状态。

## 必读资源

开始任务后完整读取：

- `references/rules.md`：事实分层、词库、标题、型号、属性和预测规则。
- `references/output-template.md`：Obsidian Markdown 固定结构。

使用 `scripts/listing-tools.mjs` 校验机械规则，不靠人工估算字符数或重复项。

## 工作流

```text
- [ ] 确认一套产品图片和补充信息
- [ ] 逐图建立事实、推断和未知项清单
- [ ] 按品类读取相关词表并排除品牌或不适用词
- [ ] 生成5个不同采购角度的标题
- [ ] 生成3套SPU/SKU与5组共15个属性
- [ ] 生成材质、反光材料、尺寸和重量预测
- [ ] 运行脚本直到valid=true且warnings为空
- [ ] 写入并复读验证Obsidian Markdown
```

### 1. 检查输入

需要一套产品图片。把同一文件夹内图片视为同一产品的不同角度，除非用户说明有多个产品。品牌或系列名未提供时，不编造品牌前缀。

### 2. 识别产品

逐张查看图片，记录 `图片可见`、`用户提供`、`合理预估`、`尚待核实`。如果核心品类在腰带、胸带、斜挎带等方向之间无法确定，先向用户确认；不要用模糊品类直接批量生成正式标题。

### 3. 读取词库

使用 `spreadsheets:Spreadsheets` 只读检查与产品最相关的工作簿。读取非空“主词/同类词”，保留文件和工作表来源。不能从表中推导搜索量排名。词库不足或不适用时自主扩展合理中文采购词。

### 4. 生成结构化草稿

按 `references/rules.md` 生成 JSON 草稿。5 条标题的角度应真实不同；目标 50–60 字。生成属性前先规划 15 个不重叠语义维度。预测字段给出候选或区间、判断依据和核实方式。

### 5. 校验

运行：

```text
node scripts/listing-tools.mjs validate --input <listing.json> --output <validation.json>
```

修正所有错误和短标题警告。再人工检查同义重复、图片真实性、品牌词和经营能力声明。

### 6. 写入 Obsidian

按 `references/output-template.md` 输出。目录为 `1688发品/YYYY-MM-DD/`，文件名使用清晰产品名；已存在时使用 `-2`、`-3` 后缀，不覆盖旧文件。写入后重新读取，核对 5 条标题、3 套型号、15 个属性、4 个预测字段和校验摘要。

## 完成报告

报告 Markdown 绝对路径、每条标题字符数、使用的词表、预测项及待核实项。词库只读，不修改 Excel。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 把词表当流量排名 | 只当候选叫法，按图片和采购逻辑选词 |
| 为接近60字重复同义词 | 补充新的结构、对象、场景或采购维度 |
| 把推测写成确定事实 | 标注预估、依据和核实方法 |
| 用包装或定制填充SKU | 只使用已确认的颜色或规格属性 |
| 15个属性换词重复 | 先规划唯一语义维度，再写属性名和值 |
| 用尺码身高体重凑属性 | 尺寸规格单独输出，属性只写产品外观结构工艺功能与场景 |
