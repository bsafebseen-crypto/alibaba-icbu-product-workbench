# 国际站自动上品工作台 MVP 设计

## 目标

在 Windows 本机运行一个中文可视化工作台。用户导入一组本地商品图片和一份词表后，可手工填写或调用兼容 OpenAI 协议的大模型生成 5 份商品标题、卖点和关键词，并把本次任务保存到本地。第一版不直接正式发布商品，为后续接入阿里国际站草稿 API 保留明确的数据出口。

## 第一版范围

- 浏览器访问本地工作台，不依赖云端托管。
- AI 设置包含供应商预设、Base URL、API Key、模型名称和“测试连接”。
- API Key 仅保存在服务进程内存中，不写入任务文件、浏览器存储、日志或 Obsidian。
- 支持导入图片文件和 CSV/TXT 词表。
- 支持两种内容模式：AI 自动生成、用户手工填写。
- 每个任务固定生成 5 个商品版本：1 个基础商品和 4 个类似品。
- 可逐个编辑标题、卖点和关键词。
- 保存任务为本地 JSON，并在工作台显示保存结果。
- 提供明确的 token 提示：只有 AI 生成和 AI 连接测试会调用模型并产生模型侧用量。

## 暂不包含

- 不在第一阶段执行阿里正式发布。
- 不保存 App Secret、Access Token 或大模型 API Key。
- 不让 AI 编造价格、材质、认证、尺寸等事实属性。
- 不自动生成图片或修改图片。
- 不同步 Obsidian；Obsidian 文档写入作为后续独立功能。

## 用户流程

1. 启动 `启动工作台.cmd`，浏览器打开本地页面。
2. 在“AI 设置”选择预设或自定义 Base URL，填写 API Key 和模型，测试连接。
3. 选择商品图片，上传 CSV/TXT 词表。
4. 选择 AI 自动生成或手工填写。
5. AI 模式生成 5 个语言版本；手工模式直接创建 5 个空白可编辑版本。
6. 在单一整洁页面中切换并编辑 5 个版本。
7. 点击“保存任务”，服务端把不含密钥的任务 JSON 写入 `data/tasks/`。

## 数据结构

任务对象包含：

- `id`：服务端生成的任务 ID。
- `createdAt`：ISO 时间。
- `source`：图片文件名、词表文件名和解析后的词语。
- `products`：长度固定为 5；每项包含 `index`、`kind`、`title`、`sellingPoints`、`keywords`。
- `generation`：`mode`、`provider`、`baseUrl`、`model`，不包含 API Key。
- `status`：第一版固定为 `prepared`。

## AI 接口

第一版统一调用 OpenAI 兼容的 `POST {baseUrl}/chat/completions`。服务端要求模型只返回 JSON，并验证结果必须恰好包含 5 个商品。生成规则：围绕同一真实商品改写语言，不添加词表和用户输入中没有的事实。

## 页面布局

- 顶部：工作台名称、运行状态、token 用量提示。
- 左栏：AI 设置和素材导入。
- 右侧主区：5 个编号标签页；每次只展示一个商品编辑表单。
- 底部固定操作区：创建手工版本、AI 生成、保存任务。

避免多列卡片同时展示大量表单，确保普通桌面宽度下文字和按钮不相互覆盖。

## 错误与安全边界

- 缺少 API Key、模型、图片或词表时显示中文字段级错误。
- AI 返回非 JSON、数量不是 5 或网络错误时，不覆盖已有编辑内容。
- 文件名经过净化，任务输出只能写入项目的 `data/tasks/`。
- 上传限制为常见图片、CSV 和 TXT，并设置单次请求体上限。
- 正式发布按钮在第一版不存在，避免误上架。

## 验收标准

- 双击启动脚本后可访问工作台。
- 手工模式无需 API Key，可建立并编辑 5 个版本。
- 使用兼容接口时能测试连接并生成 5 个版本。
- 保存后的 JSON 不包含 API Key。
- 自动化测试覆盖词表解析、五版本校验、密钥剔除、任务保存路径和主要 HTTP 接口。
