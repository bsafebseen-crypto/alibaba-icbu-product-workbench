# AI 生成四套类似品设计

## 目标

在已有“读取一个线上主产品并生成四份本地 Schema 预览”的基础上，加入一条安全的 AI 生成链路。用户上传四张类似品主图和一个副图素材池，再结合主产品原文案、自定义属性、关键词表与补充事实，生成四套可人工修改的类似品内容。

本阶段只调用用户配置的大模型接口并保存本地结果，不调用阿里图片银行上传、商品草稿保存或正式发布接口。

## 已确认规则

- 四张主图按上传顺序与类似品 1 至 4 一一对应。
- 用户可一次上传多张副图；每个类似品必须分配五张副图。
- 副图默认按稳定轮换规则分配，不能因刷新或重新渲染随机变化；用户可以手工替换。
- 标题、主题卖点、FAQ 前五条和自定义属性均可由 AI 生成，也可由用户手工填写或覆盖。
- FAQ 只修改前五条；主产品原有的第六条及以后内容保持原值。
- 自定义属性不是类目标准属性。每个类似品完整继承主产品自定义属性，AI 每套最多提出五项差异。
- 自定义属性差异可为修改、添加或删除。未被差异命中的属性必须保持原值和顺序。
- AI 不得编造材质、认证、尺寸、价格、性能或其他没有依据的产品事实。
- 所有图片和生成内容先进入本地工作台，不提交到阿里。

## 方案选择

采用“克隆加差异提案”。工作台先复制主产品内容，再让 AI 为四个类似品返回有限的结构化差异。与整表重新生成相比，这一方案更容易验证，也更符合“发布类似品”的实际操作。

不采用以下方案：

- 整张属性表重新生成：容易丢失原属性或引入互相矛盾的事实。
- 固定属性模板加关键词替换：跨产品适应性差，后续维护成本高。
- 依赖网页自动点击发布表单：容易被页面布局变化影响，也难以安全验证变更范围。

## 数据结构

每个类似品扩展为：

```json
{
  "index": 1,
  "sourceProductId": "1600000000000",
  "title": "...",
  "sellingPoints": "...",
  "faqItems": [
    { "question": "...", "answer": "..." }
  ],
  "customAttributes": [
    { "name": "Closure Style", "value": "Front Zipper" }
  ],
  "attributeChanges": [
    {
      "operation": "update",
      "name": "Closure Style",
      "before": "Front Zipper",
      "after": "Smooth Front Zipper"
    }
  ],
  "keywords": ["..."],
  "imageAssignment": {
    "mainImageIndex": 0,
    "auxiliaryImageIndexes": [0, 1, 2, 3, 4]
  }
}
```

图片只以当前浏览器会话中的文件和索引存在。保存本地任务时只保存文件名、分配关系和生成内容，不把图片二进制写入任务 JSON。

## 图片分配

页面提供四个固定主图槽位和一个支持多选的副图素材池。

副图池少于五张时禁止生成。默认分配采用确定性的轮换：类似品 1 从第 1 张开始取五张，类似品 2 从第 2 张开始取五张，以此类推；素材池不足以提供不同组合时允许复用，但每个类似品内部不得重复同一张图。

切换类似品标签时展示该商品的一张主图和五张副图。用户替换任意副图后，工作台保留手工选择，不再被自动分配覆盖。

本阶段不修改 Schema 中的图片字段。本地图片必须先通过未来接入的 `alibaba.icbu.photobank.upload` 上传并取得阿里图片地址，才能写入商品草稿。

## AI 输入与输出

### 输入

模型输入包括：

- 四张主图和本次实际用到的副图；
- 主产品原标题、主题卖点、FAQ 前五条和自定义属性；
- 用户上传的关键词表；
- 用户填写的补充事实；
- 四个类似品的图片分配关系。

浏览器在发送前把图片缩放到最长边不超过 1536 像素，并转换为质量适中的 JPEG 数据 URL，以控制请求体和模型费用。不会把阿里 App Secret、Access Token 或完整 Schema XML 发送给模型。

支持 OpenAI 兼容多模态消息的模型接收图片与文字。若模型明确拒绝图片输入，工作台允许用户选择文字回退：只使用原文案、原属性、关键词和补充事实生成，并在结果上标记“未识图”。工作台不静默回退，避免用户误认为模型分析过图片。

### 输出

模型必须返回包含四个类似品的 JSON。每项包含标题、主题卖点、五条 FAQ、自定义属性差异和采用的关键词。服务端执行严格校验：

- 必须正好四项；
- 标题非空且不超过 128 个字符；
- 每项必须正好五组非空 FAQ；
- 每项自定义属性差异不得超过五项；
- 差异操作只能是 `add`、`update` 或 `delete`；
- `update` 和 `delete` 必须命中原有属性；
- 属性名不得为空，最终属性名不得重复；
- 关键词必须来自上传词表；
- 模型不得返回图片二进制、阿里凭证或 Schema XML。

只要任一类似品不符合结构要求，整次生成失败并保留页面现有内容，不做部分覆盖。

## Schema 修改边界

本阶段继续使用已有的结构化 XML 解析方式，只修改已经可靠识别的字段。

- 标题：替换已识别的标题字段。
- 主题卖点：替换已识别的 Product Summary 字段。
- FAQ：只替换前五条；第六条及以后保留原值。
- 自定义属性：在识别到自定义属性容器后，应用最多五项已确认差异。
- 标准类目属性、品牌、省份、价格、SKU、详情、物流、分组和图片字段保持原值。

如果真实 Schema 无法可靠识别 FAQ 或自定义属性容器，工作台显示“需确认”并禁止生成 XML 预览，不使用字段名称猜测性写入。

## 页面设计

### 图片区

把当前“六张主图”改为两个区块：

- 四张类似品主图：固定四个槽位并显示对应编号；
- 副图素材池：支持一次选择多张图片，显示缩略图和数量。

在类似品编辑器中显示当前商品的一张主图和五张副图，可逐张替换。

### 内容区

- 标题继续使用单行输入框和 128 字符计数。
- 自定义属性改为结构化键值表，支持新增、删除、修改和排序。AI 变更行显示原值、新值和操作类型，并支持撤销。
- 主题卖点使用多行输入框。
- FAQ 改为五组独立的 Question 和 Answer 输入框。
- 关键词显示本版本实际采用的词，并允许人工调整。

### 操作区

模板模式新增“AI 生成 4 套类似品”按钮，并标注该操作会产生模型用量。“生成 4 份本地预览”保持独立；只有内容校验与 Schema 字段识别都通过时才能使用。

每个类似品标签显示图片、标题、属性、卖点和 FAQ 的完成状态。重新生成前如检测到手工修改，必须明确询问是否覆盖；默认保留手工内容。

## 错误处理与安全

- 缺少任一主图：指出具体编号并停止生成。
- 副图少于五张：停止生成并提示当前数量。
- AI 配置不完整：不发起请求。
- 模型拒绝图片：提示用户选择文字回退，不自动假装完成识图。
- 模型返回无效 JSON 或结构不完整：拒绝整次结果并保留现有编辑内容。
- 模型生成疑似认证、材质、尺寸或性能事实但无法从输入依据验证：标记为需人工确认，不进入 Schema 预览。
- 图片压缩只在浏览器内进行，临时数据 URL 不写入日志或任务文件。
- API Key 不写入任务 JSON、日志或 Obsidian。
- 阿里 App Secret、Access Token 和完整 Schema XML 不发送给大模型。
- 本阶段不调用图片银行、草稿保存或正式发布接口。

## 测试策略

采用测试驱动开发：

1. 图片分配测试：四张主图一一对应；副图轮换稳定；每套五张且内部不重复；不足五张报错。
2. AI 请求测试：多模态消息包含压缩图片和脱敏文字，不包含阿里凭证或 Schema XML。
3. AI 输出测试：验证四项数量、标题长度、五条 FAQ、最多五项属性差异和关键词来源。
4. 属性差异测试：添加、修改、删除正确；未修改项保持原值和顺序；重复属性名被拒绝。
5. FAQ 测试：只替换前五条，第六条及以后保持原值。
6. HTTP 测试：生成成功和各类失败均不会泄露 API Key，也不会部分覆盖服务端返回结果。
7. 静态页面测试：覆盖四主图区、副图池、结构化属性表、五组 FAQ 和模板模式 AI 按钮。
8. 浏览器冒烟测试：上传图片、切换四个类似品、手工替换副图、编辑属性、生成失败提示和结果渲染。

## 验收标准

- 能上传四张主图并固定映射到四个类似品。
- 能上传至少五张副图，并为每个类似品生成稳定的五图组合。
- 能根据图片、主产品内容、关键词表和补充事实请求兼容模型生成四套内容。
- 每套正好包含标题、主题卖点、FAQ 前五条、自定义属性差异和采用关键词。
- 每套自定义属性最多变化五项，未变化属性保持原值。
- 用户可以在生成后修改所有内容和图片分配。
- 无效或不完整的模型输出不会覆盖当前编辑内容。
- 本地预览只修改已确认字段，不调用任何阿里写接口。
- 自动化测试与浏览器冒烟测试通过后才视为本阶段完成。

## 后续阶段

本设计完成并使用真实主产品 Schema 校准字段后，下一阶段才接入图片银行上传；取得阿里图片地址后生成完整草稿 XML。再下一阶段由用户逐份确认并显式触发 `alibaba.icbu.product.schema.add.draft`。正式发布接口继续保持独立，不与草稿保存合并。
