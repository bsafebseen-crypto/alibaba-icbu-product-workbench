# 1688 自动发品模块设计

日期：2026-09-16

## 1. 目标与边界

在现有“国际站运营工作台”中新增独立的“1688 自动发品”入口，完成一个安全的单商品闭环：独立配置和授权、类目与动态 Schema、官方图片空间上传、本地编辑和预览、只读预检、单次确认发布、发布后只读核验、任务恢复。

本设计不改变现有“Obsidian 类似品上品”和“阿里国际站接口”的行为，不调用或改动 ICBU 真实商品写接口，也不通过网页自动化、内部接口或抓包接口绕过 1688 开放平台权限。

第一版不做批量真实发布。所有自动测试只使用 mock/fake；即使本机存在 Token，也不能由测试或开发流程触发真实写入。

## 2. 已确认的官方约束

- 采用“新版商品管理解决方案（商家自用版）”，适用角色是有系统对接能力的诚信通商家，且仅限商家自用。
- 商品字段和规则必须通过 `alibaba.new.product.getSchema` 动态获取，不能维护一套写死字段。
- 级联字段变化通过 `alibaba.new.product.getSubSchema` 获取。
- 发布提交使用 `alibaba.new.product.add`；请求主体由 Schema 返回的 `global` 和本地映射后的 `formValues` 组成。
- 官方方案要求配合前端 JS SDK；真实发布就绪状态必须包含 SDK 加载与初始化诊断。
- 官方没有在已查资料中提供发布幂等键，也未发现沙箱或只校验不发布接口。
- 发布返回的 HTTP 200 不能代表最终成功；必须解析业务层 `success / bizCode / bizMsg / bizData`，并使用只读商品接口再次核验。
- 超时而结果不确定时禁止自动重试写接口。可通过发布前生成的唯一货号调用 `alibaba.product.list.get` 只读查找，再用 `alibaba.product.get` 核验。

## 3. 推荐架构

采用“权限门控的完整单商品闭环”。写接口适配层存在并经过 mock 测试，但生产路由默认受多重门控保护；未满足条件时，页面只开放配置、连接诊断、类目、Schema、本地预览和预检。

### 3.1 模块隔离

新增独立模块，不复用 ICBU 客户端实例、Token、Refresh Token、浏览器存储键或任务文件：

- `src/1688-client.js`：1688 网关签名、OAuth、只读和写接口封装。
- `src/1688-schema.js`：动态 Schema 解析、字段映射、级联规则和本地预检。
- `src/1688-task-store.js`：脱敏任务持久化和版本控制。
- `src/1688-publishing-state.js`：单商品状态机、请求指纹和防重复规则。
- `src/1688-publication-reconciliation.js`：发布后的只读对账。
- `public/1688-publishing.js`：独立页面控制器。
- `/api/1688/*`：独立服务端路由。

允许复用的仅是无业务身份的基础工具或现有视觉样式；不得复用 ICBU 认证状态或发布状态。

### 3.2 密钥与 Token

- App Secret、Access Token、Refresh Token 仅作为当前请求配置或服务端内存中的短期状态使用。
- 浏览器可选择会话记忆；若用户明确选择本机记忆，也只能使用独立的 `1688-*` 键，不能与 `ali-*` 键混用。
- Token、密钥不得写入 `data`、任务 JSON、日志、异常详情或响应中的调试对象。
- 对前端返回的错误进行归一化，只返回可操作的中文原因、官方业务错误码和请求 ID。

### 3.3 OAuth 与连接诊断

连接诊断分层返回：

1. 本地配置完整性：App Key、App Secret、回调配置。
2. Token 状态：是否存在、是否过期、刷新是否成功。
3. 官方只读调用：使用类目或商品只读接口验证签名和授权。
4. 方案能力：检查调用返回是否表明缺少“新版商品管理解决方案（商家自用版）”或相关 API 权限。
5. JS SDK：检查官方脚本是否加载、`appKey / appName` 是否匹配及必要能力是否可用。
6. 写入门控：仅当以上条件通过且服务端显式启用写入时，页面才显示可确认的发布动作。

任何阶段失败都返回具体诊断，不使用笼统的 `Failed to fetch`。

### 3.4 动态 Schema 与本地表单

工作流为：

1. 搜索并选择叶子类目。
2. 通过类目 `categoryType` 映射发布场景：`cbu / industry / popular / processing`。
3. 拉取主 Schema，保存 Schema 摘要和内容哈希，不持久化认证信息。
4. 按 Schema 的字段 `type`、`required`、可见性、只读性、枚举值、长度、数值范围和异步校验标记生成本地编辑模型。
5. 字段变化需要级联规则时调用 `getSubSchema`，合并后重新预检。
6. 提交前重新读取或比对 Schema 哈希；规则变化时阻止发布并要求重新确认。

第一版只实现完成单商品闭环所需的字段组件；遇到未支持但必填的组件时必须阻止发布并明确显示组件类型，不能忽略后继续。

### 3.5 图片

- 本地先校验文件存在、允许格式和 2 MB 单图上限。
- 上传使用 `alibaba.photobank.photo.add`，`webSite=1688`，相册 ID 由用户选择或读取默认相册。
- 上传成功后仅持久化官方图片 URL、图片标识和安全元数据，不保存图片二进制或 Token。
- 任意必需图片上传失败时阻止预检通过；不得以本地路径代替官方 URL 发品。

### 3.6 预览和只读预检

预览同时展示：

- 商品卡片：标题、类目、属性、SKU、价格阶梯、库存、起订量、详情、主图和详情图。
- 请求摘要：接口名、场景、类目、字段数量、SKU 数量、图片数量、请求指纹；隐藏 Token、密钥和图片二进制。
- 缺失字段：按 Schema 路径和中文标签列出。
- 不支持字段：列出未知组件或官方异步校验要求。
- 权限门控：列出尚缺的方案、OAuth、SDK 或账号能力。

“只读预检”是本地 Schema 校验和官方只读能力检查，不冒充官方提供的 dry-run 接口。

### 3.7 状态机与防重复提交

建议状态：

`draft -> schema_ready -> preflight_failed | ready -> publishing -> verify_pending | uncertain | publish_failed -> published_verified | review_pending | verification_failed`

规则：

- 发布前以规范化请求摘要生成 SHA-256 指纹，并持久化 `publishing` 状态后才能发出写请求。
- 同一任务同一指纹只允许一次写调用。重复点击、刷新或并发请求返回现有发布记录。
- 全局写锁防止同一进程内两个 1688 发布同时越过检查。
- HTTP 超时、连接断开、不可解析响应均进入 `uncertain`，绝不自动重发。
- 已返回商品 ID 时使用 `alibaba.product.get` 核验。
- 未返回商品 ID 时按发布前唯一货号、窄时间窗口和类目调用 `alibaba.product.list.get`；必须唯一匹配后才能记录商品 ID。
- 查询不到时保持 `uncertain` 并按只读退避计划继续核验；多个匹配时进入人工处理，不自动选择。
- 成功核验保存商品 ID、请求 ID、业务错误码、商品状态、审核状态和核验时间。

### 3.8 持久化与恢复

1688 任务使用独立目录和文件前缀。持久化内容仅包括：

- 本地商品数据和安全图片引用。
- Schema 摘要、版本/哈希和类目场景。
- 状态机状态、请求指纹、写调用是否已消耗。
- 商品 ID、请求 ID、错误码、审核状态和核验记录。

服务重启后：

- `publishing` 任务恢复为 `uncertain`，只能进入只读核验。
- `verify_pending / review_pending / uncertain` 恢复只读核验计划。
- 已消耗写机会的指纹不能因重启而再次调用发布接口。

## 4. 服务端接口草案

只读和本地接口：

- `POST /api/1688/token/exchange`
- `POST /api/1688/token/refresh`
- `POST /api/1688/connection/test`
- `POST /api/1688/categories/search`
- `POST /api/1688/categories/get`
- `POST /api/1688/schema/get`
- `POST /api/1688/schema/sub`
- `POST /api/1688/images/upload`
- `POST /api/1688/preflight`
- `GET/PUT /api/1688/tasks/:taskId`
- `GET /api/1688/publications/:publicationId`
- `POST /api/1688/publications/:publicationId/reconcile`

真实写接口：

- `POST /api/1688/tasks/:taskId/products/:productKey/publish`

该路由只执行单商品发布，并检查任务版本、指纹、写锁、能力门控和显式写入开关。测试环境强制禁用真实网络写入。

## 5. 测试策略

严格按红—绿—重构推进。至少覆盖：

- 1688 与 ICBU 配置、Token、路由和任务完全隔离。
- Token 过期后刷新成功、刷新失败及错误脱敏。
- 类目场景映射和 Schema 必填字段。
- 级联 Schema 合并及规则变化冲突。
- 图片超限、格式错误、上传失败和官方限流错误。
- 未支持的必填组件阻止发布。
- 发布前版本冲突和 Schema 哈希冲突。
- 重复点击、并发点击和服务重启均不重复写入。
- 写调用超时后只读核验，不自动重发。
- 通过商品 ID 核验、通过唯一货号核验、零匹配和多匹配。
- 审核中状态持久化和恢复。
- 密钥、Token 不出现在任务 JSON、日志和前端错误中。
- 所有现有测试继续通过。

## 6. 验收

- `npm test` 全部通过。
- `git diff --check` 通过。
- 本地工作台可启动。
- 左侧出现独立“1688 自动发品”入口。
- 可完成独立配置、只读连接、类目与规则读取、本地单商品预览和预检。
- 权限不足时显示明确阻塞原因。
- 未经当前会话明确确认，不执行第一次真实发布。

## 7. 已知阻塞与后续资料

真实联调前仍需账号侧提供或确认：

- 1688 开放平台应用 App Key、App Secret、应用名称和回调地址。
- 应用已订购“新版商品管理解决方案（商家自用版）”。
- 被授权账号是可发品的诚信通商家，且没有发品处罚或类目资质阻塞。
- 官方前端 JS SDK 可在当前工作台来源下加载并完成初始化；如平台要求登记域名，需要提供登记后的 HTTPS 来源。
- 一个允许只读验证的 Access Token/Refresh Token；这些值不得提交 Git。
