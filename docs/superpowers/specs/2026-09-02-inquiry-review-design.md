# 询盘聊天读取与 DeepSeek 复盘设计

日期：2026-09-02

## 背景

当前工作台已经能完成 Obsidian 类似品准备和阿里接口配置，但不能集中查看业务员与客户的询盘聊天，也不能基于真实对话做复盘。用户希望在同一个本地工作台中查看“业务员聊了什么、怎么聊的”，并使用 DeepSeek 给出有证据的改进建议。

阿里开放平台文档提供会话列表和历史消息读取能力，但它们属于 `OKKI&TM` 类目，不应假设当前 ICBU 商品应用天然拥有调用权限。第一步必须做只读能力探测；没有权限时显示真实错误并停止，不能改用网页抓取、浏览器自动化或其他绕过方式。

这是一个新的敏感数据子系统。聊天正文、联系人信息和模型密钥不得进入 Git、普通日志或现有任务文件。

## 目标

1. 用户首次维护“业务员姓名 + 阿里账号 ID”清单，此后可按业务员同步其有权读取的会话。
2. 在工作台内查看会话列表、完整聊天时间线和可核实的基础复盘指标。
3. 只在用户主动选择会话并点击按钮后，将脱敏后的对话发送给 DeepSeek。
4. DeepSeek 输出客户需求、沟通表现、漏问信息、风险、下一步建议和参考回复，并为判断附带消息依据。
5. 聊天正文、复盘结果和 DeepSeek Key 加密保存在本机，默认保留 90 天。
6. 全流程只读阿里聊天数据，不发送消息，不修改客户、询盘、商品或订单。

## 已批准方案

采用“本地只读询盘模块 + 加密资料库 + 用户触发的 DeepSeek 复盘”。

不采用以下方案：

- 每次实时读取且不留缓存：接口不可用时无法复盘历史，分页等待也会影响使用。
- 云端数据库和多人登录：当前只有单机工作台需求，会扩大隐私、部署和权限范围。
- 后台自动把所有聊天发送给模型：费用和隐私不可控，也违背用户主动选择的边界。
- 用模型生成一个业务员总分或自动排名：主观结论难以审计，容易掩盖真实对话证据。
- 网页抓取或浏览器自动化读取聊天：权限边界不清晰且不稳定。

## 官方接口与能力探测

第一版只允许调用两个明确列入服务端 allowlist 的聊天读取方法：

- `alibaba.interaction.im.conversation.list.query`：按业务员账号 ID 分页读取会话列表。
- `alibaba.interaction.im.message.list.query`：按会话 ID 和当前业务员账号 ID 分页读取历史消息。

这两个方法使用 TOP 风格签名和网关调用。实现可以复用现有阿里签名基础函数，但必须建立独立的只读聊天适配器，不能把商品 Access Token、草稿逻辑或写接口混入该模块。

用户新增或测试业务员账号时，工作台用最小页大小执行一次能力探测：

1. 校验账号 ID 格式；
2. 调用一次会话列表读取；
3. 把成功、无数据、无权限、签名错误、限流和账号错误分开显示；
4. 只有成功或合法空列表才把账号标记为可同步；
5. 不在探测阶段读取任意会话正文。

“接口文档标注不需要授权”不等于任何 AppKey 都可调用。工作台只使用当前应用实际获得的能力，不尝试扩大或绕过阿里授权。

## 页面结构

左侧导航新增一个 `询盘复盘` 入口。此前删除的独立 `AI 接口` 导航不恢复；DeepSeek 配置属于询盘复盘页面自身。

页面主体为三栏：

1. 左栏：资料库锁定状态、业务员清单、日期范围、未回复筛选、同步状态和同步按钮。
2. 中栏：会话列表，显示业务员、客户显示名、最后消息摘要、最后消息时间、首次响应时间和未回复时长。
3. 右栏：按时间排序的完整聊天记录、基础指标、脱敏预览和 `DeepSeek 复盘` 按钮。

页面顶部显示：最近同步时间、当前筛选结果数量、待回复会话数、DeepSeek 当前模型和本次会话 Token 用量。不得虚构曝光、成交率、采购金额或其他平台未提供的数据。

## 业务员账号配置

第一版不自动发现业务员。用户首次录入：

- 本地显示名称；
- 阿里 `seller_account_id`；
- 是否启用同步。

账号保存前必须通过能力探测。相同账号 ID 不得重复添加。删除账号时，页面分别提供“只移除配置”和“同时清除此账号本地聊天”的明确选择；不会影响阿里后台账号或消息。

工作台只能读取当前 AppKey/账号权限范围内的数据。无法读取的业务员必须由管理员在阿里开放平台侧完成授权，工作台不代替权限管理。

## 同步与去重

同步由用户点击触发，不监听、不定时后台运行。每个业务员独立维护同步游标：

1. 分页读取会话列表；
2. 对新会话或 `latest_message_time` 发生变化的会话读取消息；
3. 按官方消息 ID 去重；
4. 单页成功后立即原子保存游标和数据；
5. 中断后从最后成功页继续；
6. 不自动重试权限错误和签名错误；限流只显示可重试时间。

同一消息 ID 出现内容冲突时保留原记录并标记冲突，不静默覆盖。缺少稳定消息 ID 的异常响应以会话 ID、发送时间、发送者和内容摘要组成临时去重键，并在界面标注数据质量警告。

## 基础复盘指标

本地脚本直接计算，不调用模型：

- 客户首条消息到业务员首条回复的时间；
- 客户最近一条消息后是否尚未回复；
- 当前未回复时长；
- 客户与业务员各自消息数；
- 会话持续时间和最近活跃时间；
- 按业务员、客户和日期筛选后的会话数量。

指标只陈述可计算事实。第一版不生成业务员总分、团队排名、情绪定性或成交概率。

## DeepSeek 复盘

### 配置

复用现有 OpenAI 兼容客户端的请求方式，默认 Base URL 为 `https://api.deepseek.com`。用户填写 DeepSeek API Key 和官方有效模型 ID，点击测试后才能保存。独立 `AI 接口` 页面不恢复。

DeepSeek Key 不再写浏览器 `localStorage`。它通过本地服务保存到加密资料库，读取接口永不把明文 Key 返回浏览器；页面只显示“已配置”和 Key 末四位。更换或删除 Key 需要资料库处于解锁状态。

### 主动确认

一次只复盘当前打开的一个会话。点击前显示：

- 将发送的消息条数和时间范围；
- 脱敏后的文本预览；
- 当前模型名称；
- 会产生模型 Token 用量的明确提示。

用户再次确认后才调用 DeepSeek。模型生成的回复只作为草稿显示，工作台不会发送给客户。

### 脱敏

发送模型前默认替换：

- 电话号码；
- 邮箱地址；
- 阿里账号 ID、会话 ID 和消息 ID；
- 明确出现的 Access Token、API Key 或类似凭证字符串。

业务员和客户使用稳定的会话内代号，例如 `Salesperson` 与 `Buyer`。产品名称、规格、数量、国家、交期和报价上下文保留，因为它们是业务复盘所需内容。页面展示实际发送给模型的脱敏文本，用户可以取消本次调用，但不能关闭凭证脱敏。

### 结构化结果

模型必须返回受校验的 JSON，包含：

- `customerNeeds`：已明确需求与仍缺信息；
- `buyingStage`：当前阶段及依据；
- `strengths`：业务员做得好的地方；
- `missedQuestions`：漏问或未确认事项；
- `communicationIssues`：响应、表达和推进问题；
- `risks`：误解、承诺或合规风险；
- `nextActions`：按优先级排列的跟进动作；
- `replyDraft`：供人工参考的英文回复；
- `evidence`：每项判断对应的匿名消息序号和时间。

无法从聊天确认的结论必须标记 `信息不足`。服务端校验字段、数量和证据引用；引用不存在的消息序号时整次结果标记为不可靠，不保存为已完成复盘。

资料库保存模型名称、生成时间、输入/输出 Token 数、脱敏规则版本和结果，不保存发往模型的第二份明文副本。价格会变化，因此第一版只记录 Token 用量，不显示未经实时价格配置验证的费用金额。

## 本地加密资料库

资料库位于 Git 忽略的 `data/inquiry-review/`，不复用商品任务 JSON。第一次使用时由用户设置本地资料库密码。

### 密钥处理

- 使用 Node.js 内置 `crypto.scrypt` 从密码和随机 salt 派生 256 位密钥；不保存密码或派生密钥。
- 每次启动工作台后，用户只需解锁一次；派生密钥只保留在 Node 进程内存中。
- 工作台停止后密钥自然清除。连续输错需要短暂退避，避免本机页面上的高速猜测。
- 修改密码时先用旧密码解密，再用新 salt 和新密钥原子重加密全部记录；失败时保留旧文件。

### 文件与加密

- 使用 AES-256-GCM，每个加密文件使用独立随机 nonce，并保存认证标签。
- vault 元数据只保存格式版本、KDF 参数、salt 和加密校验块。
- 业务员配置、DeepSeek Key、会话索引、聊天正文和复盘结果全部加密。
- 会话按独立文件保存，文件名只使用会话 ID 的 SHA-256，不暴露真实账号或客户信息。
- 所有写入先写临时文件、完成认证后再原子替换；损坏文件隔离并在页面报告，不自动删除。

90 天保留期按消息发送时间计算。解锁后自动清理到期消息；空会话及只依赖到期消息的复盘一并删除。用户可以按业务员清理或清空全部资料库，操作前显示准确范围并二次确认。

## 本地服务安全边界

- 服务继续只监听 `127.0.0.1`。
- 所有询盘和资料库端点只接受同源 JSON 请求，并校验 `Host`、`Origin` 和每次启动随机生成的页面令牌。
- 页面令牌只用于阻止其他网页调用本地接口，不作为资料库加密密钥。
- API 响应、错误和控制台日志不得包含聊天正文、完整联系人信息、DeepSeek Key、App Secret 或签名参数。
- 现有商品草稿和图片银行写入门禁不因本模块改变；本模块不调用任何阿里写接口。

## 服务端组件边界

新增组件保持单一职责：

- `inquiry-client`：只读 TOP 请求、允许方法校验、分页响应规范化。
- `inquiry-vault`：密码派生、加解密、原子文件操作和 90 天清理。
- `inquiry-sync`：账号游标、会话变化检测、消息去重和续跑。
- `inquiry-metrics`：确定性响应时间与未回复指标。
- `inquiry-review`：脱敏、DeepSeek 提示词、JSON 校验和证据校验。
- `inquiry-routes`：同源令牌、输入校验和安全响应。

浏览器模块只负责配置、筛选、时间线显示和明确确认，不实现签名、解密或模型密钥持久化。

## 错误处理

- 阿里能力不可用：显示接口方法和脱敏错误类别，阻止同步，不改用其他读取方式。
- 业务员账号无效：不保存账号配置。
- 分页中断：保留已成功页及游标，显示可继续状态。
- 限流：显示服务端返回的等待信息，不做紧密自动重试。
- 资料库未解锁：所有账号、聊天、同步和复盘端点拒绝访问。
- 密码错误：返回统一错误，不泄露资料库是否包含某个账号。
- 文件认证失败：隔离单个损坏记录，其余数据仍可读取。
- DeepSeek 连接、余额或模型错误：保留聊天，不生成空复盘，不自动重复扣费。
- 模型 JSON 无效或证据不存在：显示失败原因，允许用户主动重试。
- 同步期间关闭页面：服务端完成当前已发出的只读请求和原子写入后停止该同步，不继续下一页。

## 测试策略

1. TOP 签名与 allowlist：只允许两个已批准读取方法，不携带商品 Access Token，不存在写方法入口。
2. 能力探测：成功、合法空列表、无权限、签名错误、限流和账号错误。
3. 分页续跑：多页会话、多页消息、中断恢复、重复消息和冲突消息。
4. 指标：首次响应、未回复、双方消息数、空会话和乱序时间戳。
5. 加密：正确密码、错误密码、随机 nonce、认证失败、原子写入和密码修改回滚。
6. 保留期：90 天边界、部分过期消息、空会话和关联复盘清理。
7. 脱敏：电话、邮箱、账号 ID、消息 ID 和凭证模式不得进入模型请求。
8. 模型结果：有效 JSON、缺字段、虚假证据引用、信息不足和 Token 用量保存。
9. 路由安全：非同源 Origin、错误页面令牌、锁定资料库和敏感响应过滤。
10. 页面：账号配置、同步状态、筛选、三栏时间线、确认弹窗和 Key 掩码。
11. 全量回归：现有 Obsidian 上品、阿里接口、OAuth、Schema、图片银行和草稿测试全部通过。

所有自动测试只使用虚构账号和脱敏 fixture，不调用真实阿里或 DeepSeek 接口。

## 分阶段验收

### 阶段一：本地骨架与能力探测

- 加密资料库可以创建、解锁和锁定；
- 可以录入一个业务员账号；
- 只调用会话列表最小探测，不读取聊天正文；
- 明确确认当前 AppKey 是否具备能力。

### 阶段二：单账号、单会话读取

- 用户主动同步一个业务员；
- 只读取并展示一个真实会话；
- 分页、去重、响应时间和未回复状态正确；
- 用户在页面核对消息顺序和参与者方向。

### 阶段三：单会话 DeepSeek 复盘

- 用户查看脱敏预览并明确确认；
- DeepSeek 返回结构化复盘和真实消息依据；
- 页面显示 Token 用量；
- 不发送任何消息给客户。

### 阶段四：多业务员开放

- 用户逐个添加并验证业务员账号；
- 支持手动批量同步已启用账号；
- 业务员、日期和未回复筛选正确；
- 90 天清理和手动清理通过验收。

## 非目标

- 自动发现或创建阿里业务员账号；
- 读取当前 AppKey 未获授权的聊天；
- 抓取网页端聊天内容；
- 自动或人工从工作台发送阿里消息；
- 自动跟进客户、群发或定时发送；
- 监听目录或在后台定时同步；
- 业务员总分、自动排名、薪酬或处罚建议；
- 云端同步、多用户登录和远程访问；
- 修改现有商品正式发布安全边界。

## 最终验收标准

- 工作台新增可用的 `询盘复盘` 模块，旧的独立 `AI 接口` 导航不恢复。
- 当前阿里应用的聊天读取权限在读取正文前得到明确验证。
- 用户能查看每个已配置业务员的授权会话、完整时间线和确定性指标。
- 聊天正文、复盘和 DeepSeek Key 均不以明文落盘，不进入 Git 或日志。
- DeepSeek 只分析用户明确确认的单个会话，脱敏预览与实际请求一致。
- AI 结论包含真实消息依据，信息不足时不猜测，生成回复不会自动发送。
- 同步可以分页续跑、去重，并在 90 天后清理到期数据。
- 不存在阿里聊天写接口；现有商品写入门禁保持不变。
- 全量 `npm test` 通过。
