# 阿里图片写入完整 Schema 预览设计

日期：2026-08-09

## 目标

在已经上传到阿里图片银行的图片基础上，为四个类似品各生成一份包含图片的完整本地 Schema 预览。每套固定写入六张图片：一张对应主图和五张已分配副图。

本阶段只生成并保存本地 XML，不调用草稿保存、商品修改或正式发布接口。

## 数据来源与映射

- 每个类似品继续使用现有 `imageAssignment`：`mainImageIndex` 指向四张主图之一，`auxiliaryImageIndexes` 按顺序指向五张副图。
- 图片银行上传结果继续保存在 `photobankUploads`，主图键为 `main:N`，副图键为 `auxiliary:N`。
- 写入顺序固定为 `scImages_0..5`：第 0 张是主图，第 1 至 5 张是五张副图。
- 每张图片必须同时具备阿里返回的 `fileId` 和 `photobankUrl`；缺少任何一个值都停止生成，不使用本地 data URL 或猜测值补齐。

## Schema 处理

`analyzeProductSchema` 增加对图片字段 `scImages` 的识别和现有图片数量摘要。图片识别状态独立展示，不改变已有标题、主题卖点、FAQ 和自定义属性的识别规则。

`createProductPreview` 在传入 `alibabaImages` 时执行图片替换：

1. 要求恰好六张图片并逐张验证 `fileId`、`url`。
2. 复用主产品 Schema 中现有 `scImages` 行作为结构模板。
3. 生成 `scImages_0..5`，同时写入对应 `fileId` 和 URL。
4. 保留 Schema 中所有其他字段、规则和未编辑内容。
5. 返回结果的 `changedFields` 增加 `images`。

如果没有传入 `alibabaImages`，现有“生成 4 份本地预览”行为保持不变，仍可只预览文案和属性。

## 工作台交互

图片银行区域新增“生成含图片的完整预览”按钮：

- 四套图片分配全部完成且所需图片均已上传成功后才可点击。
- 点击只把映射后的 `fileId + photobankUrl` 连同四套商品内容发送给本地服务。
- 成功后四套商品各自保存完整预览 XML，并明确提示“未创建草稿、未发布商品”。
- 原“生成 4 份本地预览”按钮保留，便于在尚未上传图片时先检查标题、卖点、属性和 FAQ。

重新选择主图、副图或调整副图分配后，对应完整图片预览视为过期，必须重新生成；已经上传且未变化的图片不重复上传。

## 安全边界

- 本阶段不调用 `alibaba.icbu.product.schema.add`、`update` 或任何发布接口。
- 不把 App Secret、Access Token、Schema XML 或图片银行信息发送给 AI 模型。
- 任务文件只保存图片银行的 `fileId`、URL、原文件名和分配关系，不保存 base64 图片或凭证。
- 任何字段结构无法识别时直接报错，不构造“最小 XML”替代真实 Schema。

## 错误处理

- 图片不足、分配重复、上传结果缺字段：指出具体商品与图片槽位并停止。
- 主产品没有可识别的 `scImages` 结构或少于一个可复用行：停止并提示重新读取主产品 Schema。
- 四套商品中任一套生成失败：不覆盖当前四套预览，避免部分成功造成状态混乱。
- 网络上传中断沿用现有续传逻辑；已经成功上传的图片不重复提交。

## 测试与验收

1. Schema 单元测试：真实风格 `scImages` 样例能写入六组正确 `fileId + URL`，其他 XML 内容保持不变。
2. 校验测试：数量不是六张、缺少 `fileId`/URL、缺少图片字段均明确失败。
3. 映射测试：四套商品分别取得正确主图和按顺序排列的五张副图。
4. HTTP 测试：四套完整预览全量成功才返回，且没有任何阿里写接口调用。
5. 页面测试：完整预览按钮在上传未完成时禁用，完成后启用，并展示本地-only 提示。
6. 回归测试：原内容预览、图片银行上传、AI 生成和任务保存行为继续通过。

完成标准：四套完整预览中的 `scImages_0..5` 与工作台当前图片分配逐项一致，自动化测试通过，并在浏览器中验证按钮状态和结果提示；全程不创建阿里草稿或正式商品。
