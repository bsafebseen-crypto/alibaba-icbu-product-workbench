# 国际站经营后台框架与商品池设计

日期：2026-08-11

## 目标与范围

把现有单页自动上品工具升级为可长期扩展的国际站经营后台，并新增基于本地任务的“商品池／草稿与待发”页面。设计借鉴参考面板的信息密度、表格结构、分级工具栏和浅色业务区块，但不复制其品牌、数据或具体页面。

本期不接入新的阿里写接口，不保存阿里草稿、不修改线上商品、不正式发布。现有图片银行上传继续保留明确确认弹窗。

## 信息架构

左侧继续使用用户已经选定的自动收缩导航，展开后显示文字和说明，收起后只显示图标：

1. 总览
2. 自动上品
3. 商品池
4. 关键词库
5. AI 接口
6. 阿里接口

页面顶部使用轻量状态栏，不重复放大标题。状态栏显示本地服务、阿里授权、当前批次以及最后保存时间。导航和状态栏固定，主内容独立滚动。

## 视觉语言

- 页面背景使用低饱和米灰色，内容区域为白色或极浅蓝灰色。
- 正文采用深墨色，次要信息采用中性灰；不使用大面积渐变、发光边框和玻璃效果。
- 蓝色用于主要操作和商品池，橙色用于待处理，红色只用于错误和危险操作，绿色用于已经完成。
- 业务区块采用细边框、2–4 像素彩色左边线和浅色标题条；阴影仅用于抽屉与浮层。
- 正文字号不低于 14px，表格正文不低于 13px，避免参考页面过小的字号。
- 图标使用统一线性 SVG，不混用 Emoji。
- 控件圆角保持 6–10px，按钮分为主操作、次操作和危险操作三种层级。

## 总览页

总览只展示可行动的信息：

- 当前批次：商品数量、已完成、待检查、失败。
- 阿里连接：授权状态、Token 状态、最近验证时间。
- 今日任务：待生成内容、待上传图片、待生成完整预览、待保存草稿。
- 最近批次：最近五个本地任务及其状态。

本期数据全部来自本地任务，不伪造曝光、点击、询盘或销售指标。

## 自动上品页

保留现有自动上品能力，并把操作重排为清晰的阶段工具栏：

`准备素材 → 关键词 → AI 内容 → 图片银行 → 完整预览 → 保存本地任务`

每个阶段显示三种状态：未开始、待检查、已完成。原有标题、四张主图、副图池、自定义属性、主题卖点和 FAQ 编辑器仍然存在；商品详情使用纵向表单，避免把大量属性横向铺在总表中。

## 商品池／草稿与待发页

### 页面结构

页面从上到下分为：

1. 状态说明条：解释本地任务、阿里草稿和正式发布的差别。
2. 全局工具栏：新建批次、导入 XLSX、导出、刷新、批量操作。
3. 阶段筛选条：全部、待补充、待检查、完整预览已生成、草稿失败、已保存本地。
4. 商品池表格。
5. 当前批次区：显示当前四个类似品，可折叠。

### 表格字段

默认列保持克制：

- 选择框
- 本地任务编号
- 商品标题
- 主产品 ID
- 商品序号（类似品 1–4）
- 内容完成度
- 图片状态
- Schema 状态
- 当前阶段
- 最后更新时间
- 操作

标题、属性、FAQ、图片等完整内容不横向展开；点击行或“编辑”按钮打开右侧详情抽屉。

表格支持搜索、状态筛选、排序、列显示、冻结首列、分页和全屏。第一期只对本地任务执行批量导出和状态操作，不提供批量发布。

### 行内状态

每行最多展示三个状态标签，其余问题合并为“还有 N 项”。可识别的问题包括：

- 标题为空或超长
- FAQ 不足五组
- 自定义属性为空
- 缺少主图或副图
- 图片银行尚未完成
- Schema 字段未识别
- 完整本地预览过期或尚未生成

点击状态标签打开对应详情，不在表格里堆叠长错误文本。

## 商品详情抽屉

右侧抽屉包含六个标签页：

1. 概览：来源、状态、关键词和完成度。
2. 图片：一张主图、五张副图以及图片银行结果。
3. 文案：标题、主题卖点和采用关键词。
4. 属性与 FAQ：结构化自定义属性和 FAQ 前五条。
5. Schema 预览：变更字段摘要和本地 XML 状态。
6. 日志：生成、上传、预览和保存时间线。

抽屉允许编辑本地内容，但任何外部写操作仍必须回到明确命名的按钮，并保留二次确认。

## 本地数据流

商品池读取 `data/tasks/` 中已经保存的任务 JSON。服务端增加只读任务列表和单任务读取能力，浏览器把每个任务中的四个类似品展开为商品行。前端筛选、排序和分页不修改任务文件。

本期不引入数据库。任务量较小时继续使用 JSON，避免为了视觉改版提前增加 SQLite。未来出现数百个批次、复杂标签关系或跨任务统计需求时，再单独设计迁移。

任务摘要包含：任务 ID、创建与更新时间、来源产品 ID、生成模式、四套商品状态、图片银行完成情况和完整预览状态。凭证、Base64 图片和 AI API Key 不进入列表响应。

## 错误与空状态

- 没有本地任务：显示一个明确的“创建第一批商品”入口。
- 某个任务文件损坏：商品池继续加载其他任务，并把损坏文件列为不可打开的异常项。
- 本地服务断开：页面保持已有内容，只禁用需要服务端的操作。
- 外部凭证失效：只影响阿里相关步骤，不影响查看和编辑本地任务。
- 表格无筛选结果：显示清空筛选按钮，不显示空白大区域。

## 实施边界

第一期实现：

- 新后台框架与视觉变量
- 总览页
- 商品池／草稿与待发页
- 本地任务列表与只读详情
- 右侧详情抽屉
- 自动上品页面的阶段状态条与视觉统一

第一期不实现：

- 阿里 `schema.add.draft`
- 正式发布
- 直通车
- 竞品抓取
- 搜索量、询盘、曝光等外部数据
- 多用户账号和云端同步

这些能力需要真实 API 权限和独立的安全设计，后续按模块逐一接入。

## 测试与验收

1. 现有自动上品、AI、图片银行和 Schema 测试继续通过。
2. 本地任务列表不得返回 Secret、Token、API Key 或 Base64。
3. 商品池能正确把一个四套类似品任务展开为四行，并展示各自状态。
4. 搜索、筛选、排序、分页和详情抽屉可在浏览器中操作。
5. 导航收缩与展开时，桌面宽度和常用笔记本宽度均不遮挡主内容。
6. 所有表格状态仅基于真实本地数据，不生成虚假经营指标。
7. 页面控制台无错误，键盘可以访问导航、工具栏、表格和抽屉。
8. 本阶段浏览器测试不调用阿里草稿或发布接口。

验收结果应是一个更像专业经营后台的工作台：信息密度高但可读，能查看和管理本地商品批次，同时保留现有安全边界。
